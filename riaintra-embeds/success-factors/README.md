## Hire automation setup

Create an automation in the site's Wix dashboard with the **Velo code trigger**. Use the example below in **Set Payload Data Structure**, and copy the trigger ID generated by Wix. In Wix Secrets Manager, set `SKANDI_HR_HIRE_AUTOMATION_TRIGGER_ID` to that ID. Select and configure the desired automation action, then activate it. `@wix/automations` and `@wix/essentials` are already declared in the root package. The backend-only `backend/SKANDI_CORE/hireAutomation.js` invokes the trigger after the existing Recruiting and HR authorization checks and successful hire; it is not a public web method.

The example contains fictional data. `contactId` is sent only when the linked employee has a verified Wix contact UUID; a Wix member ID is not substituted. Mark `contactId` in the trigger builder if an action requires a Wix contact, and handle hires without one. If no offer was prepared, `offerPrepared` is false and offer-specific strings are empty. The payload contains structured fields, not the completed HTML or a signed document; configure the chosen automation action accordingly. Offer details are visible only to HR managers and are not sent to diagnostic events.

A confirmed trigger is not retried automatically. If Wix does not confirm an attempt, check the automation history before using **Retry hire automation** on the candidate profile: a timeout may occur after Wix accepted the event. The same `eventId` is retained for the retry; configure downstream actions to deduplicate by that ID where supported. No Wix Automation, secret, database schema or live site is changed by this repository update.
